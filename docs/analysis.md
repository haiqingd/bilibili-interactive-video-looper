# 剧情分析与展示细节

本页解释地图聚合、结局识别、评分状态搜索与完整性边界。快速开始和公开体验入口见 [README](../README.md)。

## 大流程的阅读方式

可选的章节总览根据标题中的章节前缀分组；无明显章节时按图的层级分段，分组仅影响展示。案例从 388 个片段收成 12 张总览卡片，较大的章节继续按情节标题分组。第五天 A 分线默认只展示 7 张情节/出口卡片。

循环区域按已识别的强连通分量收纳，保留入口与出口；展开时展示内部连线。超过 24 个片段的区域先看两层邻域，侧栏仍列出全部成员，可以切换到任意片段。案例中 70 个片段的循环入口先展示 22 张局部卡片。带出口的循环不标为死循环。

连续的单入口、单出口片段可合并为卡片，点击可展开。被收纳的选择、条件、变量更新和结局攻略不删除。跨区域连线保留原始选项集合，多个相同区域间的连线合并展示数量。

精简地图默认「合并相同片段」：只有标题、按顺序排列的问题与选项、跳转目标 ID、条件、变量更新、隐藏／默认选项设置完全一致的非结局片段才归并。原始片段 ID、媒体 CID 不参与判等；不会仅按同名或归并后的目标卡片判等。卡片标明归并数量，详情展示共同选项并可切换原始 ID；所有入口和原始选项键保留，重复的共同出口文字只显示一次。可取消勾选恢复分开的节点，此偏好支持 URL、刷新与前进后退。完整节点视图、片段列表与逐步攻略保留每个原始节点及回访步骤；结局仍按已有的结局归并规则展示。

同一问题的选项通向至少两个不同结局时，地图用橙色菱形、加粗边框及「结局分岔」标记，卡片与连线上直接标明「选项 → 结局名称」，关闭普通连线文字时仍显示。详情列出完整对应关系、条件、变量更新，可点击定位结局。只跟随无条件、无变量更新、唯一出口的自动跳转；后续仍有选择、条件、缺失片段或循环时不推定直通。条件选项显示条件，自动分流不显示伪造的手动选项文字。结局按已有的同名归并身份判断，不把同一结局的多个原始节点计为多个结局；标记描述跳转去向，不新增可达性或最短路线结论。章节与循环收纳卡片标明内含分岔点数量，区域详情提供定位入口；完整节点、归并节点和逐步路线均支持标记。

自动跳转不展示伪装成手动选择的选项文字；地图、片段详情、攻略、复制文本和结局对比一致处理，条件及评分变化仍保留。

普通连线统一为中性色；只强调当前选择或攻略。默认关闭密集的连线文字，选中片段后的侧栏显示完整内容。长流程首次打开保持可读比例，「全图」用于查看整体，小地图用于移动。手动开启「只看当前攻略」后按每次转换展开，45 步的攻略显示 46 个发生位置；重复片段不会合并而导致步数丢失。

地图、结局导航、区域成员和片段列表共用页面滚动，桌面端滚动长导航时地图保持可见。普通滚轮滚动页面，Ctrl／⌘ + 滚轮缩放地图；手机支持拖拽和双指缩放。全屏模式铺满浏览器窗口，保留当前比例与阅读位置，滚轮直接缩放，Esc 或「退出全屏」返回；背景停止滚动，全屏片段列表可独立滚动。章节／情节使用蓝色，循环使用琥珀色，连续片段使用青绿色，起点使用紫色；明确识别的好／坏结局分别使用绿色／红色，并保留文字分类。

## 结局名称与 HE／BE

结局列表默认按好结局（HE／GE）、坏结局（BE）、其他或未知分组，同组按名称 A–Z（中文按拼音、数字按自然顺序）排列。可切换名称 A–Z、Z–A 或攻略步骤从少到多；结局对比和标注下拉框遵循同一顺序。排序写入 URL，可刷新、分享并通过浏览器后退恢复；不改变节点 ID、可达性或最短路线。

- 打开已保存攻略即自动匹配结局片段标题中的明确 HE、BE、Happy/Bad Ending 和中文分类；多种分类同时出现时保留为未知。不会把胜利、失败、分数高低或角色死亡直接当作 HE／BE。
- 在线解析在读取每个结局节点时先识别标题中的名称。流程采集与路线验证完成后，自动对未识别名称的节点读取视频关键帧，完成后才结束解析任务，无需用户额外启动。优先复用同一 CID 的已保存名称，只对不同视频片段执行一次 OCR；识别失败或风控会保存流程、截图和已完成名称，并明确列出未识别数量。播放单段媒体优先采样片尾约 25 秒（13 帧）；识别失败时加密采样最后 3 秒，再检查最初 12 秒，覆盖先显示卡片再长篇讲解的作品。使用本地中英 OCR。至少两帧出现一致文字且置信度足够才采用；不同分类冲突时不自动分类。没有明确分类的「结局：名称」只补名称。
- OCR 结果显示「待核对」，保留最多三张证据图、采样时间和识别原文。可以修改名称与分类并点击「确认并保存标注」；人工标注不会被再次 OCR 覆盖。原始标题、变量、攻略路线和可达性结论不受标注影响。
- 标注独立保存在 SQLite，截图保存在 `data/ending-evidence/`。导出 JSON 包含名称、分类及原文；截图文件需要单独备份整个 `data/`。导入时丢弃另一台机器的截图路径。
- 已识别的同名结局在导航、攻略库计数、结局对比和精简地图中合并；仅规范空白、全半角、大小写和分隔点，不做模糊相似度合并。未知名称即使原始标题相同也保持独立。同名结局默认采用各节点中步骤最少的已验证路线；路线下拉框保留所有到达节点，原节点 URL、评分条件、导出数据和完整节点视图仍保留。同名节点分类冲突时显示未知并提示核对。
- 「结局详情与标注」可查看每个节点的证据、人工修正或重试识别，不再是解析必需的后续步骤。
- 同次批量识别中相同 CID 只读取一次。再次打开攻略复用保存结果。批量默认跳过已识别名称；主动选择当前结局可重新读取。遇到 412、429、播放受限或 OCR 失败停止批次，已经完成的结果保留。Cookie 只用于当次 API 请求，不写入数据库、URL、浏览器存储，也不转发给媒体 CDN。
- 片尾无卡片、文字太短暂、字体复杂、画质低、结局卡片只出现在未采样的中间段、只有多个结局的汇总列表时，仍可能识别失败或误读。因此保留未知与人工核对，不宣称自动识别涵盖所有作品。当前仅支持播放接口返回的单段 MP4；分段媒体不拼接。

## 导航与结局对比

关键视图使用 `#/explore?...`、`#/library?...` 和 `#/authors?...` 路由。打开攻略、选择结局、切换流程详细度、进入章节/循环/片段、返回结局导航、切换地图/列表、勾选展示选项及结局对比都会形成浏览器历史。支持后退、前进、刷新及直接打开分享链接；链接引用当前数据库中的攻略 ID，因此另一台独立数据库需先导入同一攻略。Cookie 不进入 URL 或浏览器历史。

点击「对比两个结局」选择两条已验证路线。显示相同问题的不同选项、分歧时的条件、选择前后变量，并从条件表达式向前追溯相关赋值（包括复合赋值），以橙色标注对应节点。环内重复问题按发生次数对齐。紫色对应 A，青色对应 B，共同边为金色。

对比只解释两条已有路线，表达式依赖不是最小因果干预证明，也不意味着某个选择是到达结局的唯一方式。随机或部分解析的限制仍然保留。

## UP 主互动作品目录

使用 `/x/space/wbi/arc/search` 获取投稿，并完成文档规定的 WBI 请求签名。依据返回的 `is_steins_gate` 标记筛选；标题包含「互动」不能单独证明是互动视频。缺少标记的投稿明确报告为未分类。

每次读取 30 个投稿，按发布时间翻页，显示已检查数量和剩余页。页面同时合并本机已解析作品，并持久化成功读取的目录页；再次打开可以读取缓存。点击「刷新投稿列表」成功后才替换旧目录，访问失败时保留旧内容。

目录页登录 Cookie 仅保留在当前页面内存中，可用于随后选中的解析；进入解析时清空输入，不进入目录缓存、SQLite 导出或日志。接口参考：[用户投稿列表](https://github.com/alittlehuaji/bilibili-api-collect-mirror/blob/master/docs/user/space.md)、[WBI 签名](https://github.com/alittlehuaji/bilibili-api-collect-mirror/blob/master/docs/misc/sign/wbi.md)。签名是该接口正常请求参数的一部分，不保证解除风控。

## 解析方法

真实采集使用三个只读接口：

| 接口 | 用途 |
| --- | --- |
| `/x/web-interface/view` | 视频标题、作者、入口 CID |
| `/x/player/v2` | 读取 `interaction.graph_version` |
| `/x/stein/edgeinfo_v2` | 各片段的 `questions`、`choices`、`condition`、`native_action`、`hidden_vars` 和 `is_leaf` |

没有依赖一个能够直接返回完整剧情与全部结局的接口。我们从入口广度遍历所有选项跳转，包括条件当前不成立的分支；每个片段只采集一次。原始节点响应保存在 `raw_edges` 中。请求间隔至少 350 ms，一次仅运行一个在线采集任务；遇到节点失败立即停止请求，保留待采集节点占位和部分结果。

接口字段参考：[互动视频接口研究](https://github.com/alittlehuaji/bilibili-api-collect-mirror/blob/master/docs/video/interact_video.md)。辅助核对了 [bilibili-api 历史实现](https://github.com/Nemo2011/bilibili-api/blob/51914ea/bilibili_api/interactive_video.py)，项目未引用其代码或依赖其 SDK。以上为社区研究，实际接口可变。

## 为什么不能只按片段找最短路

同一片段可能在「线索数 = 0」和「线索数 = 2」时提供不同选项。分析器以 **(片段 ID、当前问题序号、未来仍可能读取的变量值)** 为去重状态：先检查选项条件，再顺序执行该选项的变量更新，最后跳转。无跳转的选项进入同片段下一问题；跨片段时保留已累积的分数。

先对所有分支和每条连续赋值进行反向变量活跃性分析，计算每个问题未来需要的输入。后续不再读取的历史标记、被赋值覆盖前的旧值不再区分状态；仍读取的评分保持精确值，不按正负或区间随意截断。赋值右侧的读取也保留，以维持除零、数值范围等错误检查。每个去重状态保留一个完整的真实变量实例，攻略的每一步与最终评分仍沿同一条可重放路径。算法参考：[Cornell 反向数据流与变量活跃性](https://www.cs.cornell.edu/courses/cs4120/2022sp/notes/dataflow/)。

案例 `BV1kE7K6KEZN` 原搜索在 20,000 状态时截断，只找到 15 个可达结局；优化后 10,043 个状态完成全部 371 个片段和 55 个结局的分析，没有提高搜索上限。该图虽声明随机变量，但没有任何条件或更新引用它，因此不再仅凭声明降级为部分分析。现有示例攻略已重新计算并保留收藏与分类。

所有转换权重为 1，使用广度优先搜索和前驱记录得到最少转换路线，**包含自动跳转**，不表示最短观看时长。初值来自入口接口响应，可能受当前登录会话影响；它不是对任何历史游玩状态都成立的攻略。

图结构通过迭代 Kosaraju 算法找强连通分量，标记「含环区域」。另外分析可达状态图，只有条件已知、状态完整、无任何出口的循环分量才标为「已确认状态闭环」。因此累积加分的回访不会被简单认成死循环。

## 完整性与边界

这是一个能运行、能保存、能验证确定性条件剧情的第一版。页面有清晰的完整性状态；遇到以下情况会降级为部分分析，不能声称已证明所有结局和全局最短路线：

- 上游节点读取失败或达到采集上限（默认 1,500 节点）。未知节点不当成结局。
- 条件或变量更新引用随机变量时：当前不猜测其取值域、刷新时机或概率。不使用单次采样值证明可达性。依赖随机值的分支保留原始条件，相关路线待验证；独立于随机值的路线仍可验证。
- 未支持的表达式、问题类型或中途新增但没有已知初值的变量。
- 自动问题有多个同时成立的选项：优先级未经验证，不能随意当成人工可任选的路径。
- 无限增长的分数导致无限状态空间；默认上限为 20,000 状态、300 次转换。

表达式解释器支持数值、布尔值、括号、`&&`、`||`、`!`、比较、`===`/`!==`、`+ - * / %` 和分号分隔赋值（含 `+=` 等）。使用独立解析器保留 JavaScript 运算优先级、短路与数值/布尔严格相等规则，**不使用 eval**。函数调用、属性访问、索引、三元表达式等未支持语法会明确报待验证。非法、过深或过长表达式也会拒绝。
